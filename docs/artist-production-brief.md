# LIMITLESS · Artist Production Brief（A6）

2026-10-17 · 用于专业角色美术估价与制作范围确认，**不是已下达的委托/付款授权**。建议基础：Blender Studio Snow v4.2；可在未来获批准后改用通过实检的PolyOne。当前项目状态仍为 **BLOCKED BY ART ASSET QUALITY**。

## 目标角色与美术方向

成年男性动漫游戏角色，**Gojo Satoru-inspired character presentation**。高挑修长、视觉约190cm、浅色皮肤、长四肢、优雅清晰的全身剪影、精致双手；白色设计感尖发、深色高领长袖制服、独立眼罩，以及摘眼罩后有辨识度的动漫面部。

目标是成熟商业动漫游戏角色资产水平。重点在眼眶/鼻底/口唇/下颌的真实三维结构、主次发束与后脑造型、服装完整性和动态稳定性。不是把基础脸拉长、拼锥体头发或用皮肤外扩壳制作制服。不得使用提取/破解游戏模型或要求复制原始游戏网格。所有新增部件需记录合法来源；基础网格许可不授予Jujutsu Kaisen角色IP使用权。

工作流：可编辑Blender源 → 自包含GLB → 现有Character Adapter → Three.js / LIMITLESS。美术师负责造型/拓扑/权重/修形/动作的艺术质量；工程方负责接口、自动检查和浏览器集成；最终验收由人工逐项评审及项目所有者确认。不要以脚本PASS代替美术审核。

## 优先委托范围：肩袖与双手试作

先提交独立上半身候选：颈部、锁骨、肩部、胸背、上臂、腋下、高领长袖和双手；包含可编辑控制网格、UV、骨架、蒙皮和可导出修正。核心是证明衣领/袖窿/袖山与人体运动关系，以及拇指对掌、掌指体积和腕前臂连接。不得通过调整相机、灯光、减动作幅度或增加细分掩盖缺陷。

必须提交两端同姿势的真实渲染及连续播放：

| 部位 | 姿势与证据 |
|---|---|
| 肩袖 | 自然垂臂；前举45°/90°/120°；侧举45°/90°/120°；上臂内外旋；弯肘；组合施术姿势；正/侧/后方看肩顶、领口、腋下和袖口 |
| 手 | Rest、张手、半握拳、握拳；拇指对食指/中指；掌面/手背/指缝/拇指根部；双手交错与腕旋转 |
| 拓扑/权重 | 肩袖、锁骨、腋下、指根、拇指控制网格线框；关键骨骼权重图；独立手指区域及过渡解释 |
| 实时导出 | Blender原生、Blender导出用LBS版本、Three.js实际GLB分别对照，标识文件SHA、姿势/时间、相机、光照和渲染设置 |

首轮完整制作/测试后，若肩顶平切、袖山硬块、领口尖塌、腋下严重塌陷或拳态/对掌明显自交仍存在，列出原因与必要返工，不扩大制作范围。试作通过只批准该范围；全角色后续工作需要另行授权，本轮没有启动Milestone B–E。

## 硬性中性验收门槛

顺序：**VFX OFF → Bloom OFF → Emission OFF → Post Processing OFF → Neutral Material + Neutral Lighting → Character Only**。先用统一灰模检查结构；再看无发光的基础材质。无展示台/能量球遮挡，固定曝光、焦距、相机和灯光。通过后才允许材质演出和VFX展示。概念图或AI图片不能替代真实资产渲染。

六项分别达到至少 **7/10**，不得平均抵消低分；未检查记`null / NOT REVIEWED`。每项列出实际可见缺陷、依据、帧/视角与文件。7分意味着精致、稳定、设计明确且多视角/多姿势成立；3–4是粗模，5–6仍需修整，不能因为代码通过就给7分。

| 核心项 | ≥7分必须证明 |
|---|---|
| 结构 | 成年比例、躯干/四肢体积和自然连接，正侧面都成立，无拼接断层 |
| 面部 | 可辨识的成年动漫结构，眼鼻唇耳下颌连贯，侧面/仰俯视不失形 |
| 手部 | 掌指结构精致，张手/拳态/对掌体积稳定、合理接触，无明显撕裂穿插 |
| 肩袖 | 袖窿/锁骨/腋下边流和布料空间合理，规定抬臂范围没有平切硬块/塌陷 |
| 服装 | 领、袖、躯干、裤鞋统一完整；厚度、褶皱和运动关系可信 |
| 整体silhouette | 高挑修长、有设计辨识度，发型/服装/人体组合在全方向均成立 |

完整角色另需正面全身、背面、左右严格侧面、45°、面部特写（正/侧/45°/仰俯）、手部特写；眼罩戴/摘两态。六项达标也不豁免其余动画、材料和技术缺陷。仅VFX开启时好看则FAIL。

**与A4门禁的关系：** [旧规格](character-art-spec.md)和现有验证器的5分是历史最低拒绝阈值，不是A6交付合格线。A6上述六项必须≥7，本简报对它们优先。当前代码未改，可能接受5–6分的结构完整审核记录；因此工程PASS不能授权发布，需人工按A6复核并绑定GLB哈希。不得伪造分数或APPROVED来绕过此差距。

## 实时技术合同

- `.blend`可编辑，完整网格/UV/骨骼/权重/材质/贴图/动画/修正形态；不以不可编辑缓存替代源资产。
- `.glb`自包含，米制，Y轴向上，面向+Z，脚底近Y=0；完整含发高度建议1.8–2.1m。两个脚底及前后朝向helper供验证，不导出灯光、摄影机或VFX。
- 项目采用LBS且每顶点最多4个非零影响、权重归一、数据有限、无异常绑定矩阵。此为项目合同，不是宣称GLTF规范仅支持4影响。不可依赖未转换的DQ、B-bones、Lattice、CorrectiveSmooth或运行时Python。
- 约束/驱动结果须烘焙到普通骨骼TRS或morph权重轨道；GLB中的修形必须确实参与动画。源与导出形体若存在差异须量化并做人工审查，不能只证明两个简化副本一致。
- 当前验证器不接受sparse accessor或未批准的必需扩展/压缩。先交未压缩标准GLB；后续优化另行验证。不以固定多边形数保证帧率，提供实际顶点/三角形/材质/骨/纹理内存和1080p目标机测试数据。
- 材质保留作者制作，使用`authored`策略；贴图在GLB内完整可读，不依赖Blender着色节点或旧模型材质名重涂。

| 逻辑动画 | 时长 | 必须对齐的事件 |
|---|---:|---|
| Idle | 4s | 自然呼吸，首尾循环和切入切出平顺 |
| CastBlue | 5s | 释放1.65s，手与挂点一致 |
| CastRed | 4s | 释放1.4s，指尖与手势稳定 |
| CastPurple | 8s | 释放4.6s，双手接触/间距合理 |
| RevealEyes | 2.4s | 眼罩接触状态提交0.92s |
| CoverEyes | 2.4s | 眼罩接触状态提交1.32s |

动作从0开始。内部名字可不同，由JSON映射唯一节点/clip；适配器不自动重定向。`Blindfold`是独立眼罩几何节点/组；`FX_Hand_L`、`FX_Hand_R`、`FX_Center`为骨或helper挂点，跟随动作而不是依赖顶点编号。标明挂点位置/轴与局部偏移；对蓄力、释放、收招及取消后的世界位置取证。保持现有技能节奏、UI/VFX，不能以新资产为由改写`effects.ts`。

## 交付、验收与交接

交付分为源资产包、实时包、证据包、许可包：

1. 源：独立版本`.blend`、外部贴图或已打包纹理、建模/导出说明、所需工具版本。
2. 实时：自包含GLB、manifest映射、六段动画、眼罩与挂点；若是局部试作则明确其未包含完整角色接口，不伪造production PASS。
3. 证据：固定参数的Blender和Three.js同姿势真实图/连续视频、线框、权重、测试结果、问题列表；原生和导出资产分别注明哈希。
4. 许可：作者、来源、版本、完整文本、部件清单、修改记录和衍生GLB分发权。Snow保留既有署名；新增工作需约定客户可编辑、修改和网页分发的权限，不能对Snow部分追加冲突限制。

候选源放 `blender/artist-assets/<asset-id>/`，实时包放 `public/models/character-production/incoming/<asset-id>/`。不要覆盖正式文件，不修改active映射。接入步骤见 [character-integration.md](character-integration.md)。

工程验收复用 `scripts/audit_deformation.py`、`scripts/audit_contacts.py`、`scripts/render_character_audit.py`、`scripts/capture_character_audit.mjs` 和 `scripts/validate-production-character.py`。现有诊断若依赖旧骨名/网格索引，要适配新资产并复核检查覆盖范围，不能假设任意骨架自动适用。动画采样覆盖完整区间及旧30fps时间基准下CastRed40–48帧对应时刻；交付FPS不同时按秒映射，不漏掉释放附近异常。

需要检查非有限数据、异常权重、边伸长/收缩、接触/穿插、UV接缝和正常关节弯曲的区分。保留现有旧头发退化面FAIL，不能从报告删掉以换取全局PASS。再做六动作、重复触发、取消、眼罩、挂点、加载、窗口和触屏回归。最终审核记录必须由人工签名、绑定准确GLB SHA-256；用户批准之前不能发布。

请有意承接的美术师提供相关作品：无特效灰模多视图、动漫脸和白色发束、长袖抬臂、拳态/拇指对掌、实际glTF/GLB播放。请分阶段报价并说明交付范围、修订次数、未知风险和排期假设。工程方不承诺自动完成未委托的美术工作。
